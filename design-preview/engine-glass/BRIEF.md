# 引擎板块玻璃动效：three.js 试点任务书

来源：与用户在设计对话中确定（2026-10-05）。`reference-handwritten-webgl2.html` 是我手写的 WebGL2 参考版，用来对照目标效果和三个场景的内容；它不是要交付的实现。

## 目标

把首页“让有限的算力，承载更多任务”（`#engine`）左侧三层玻璃板，用 three.js 重做成高质感的 WebGL 玻璃。先做**独立试点页**（`design-preview/engine-glass/index.html`），用户确认后再接入首页，用户在这一步之前不要改 `website/`。

## 设计约束（来自 DESIGN.md，违反即返工）

- 配色：黑、石墨、银白。**不要蓝紫色辉光、不要彩色渐变**。蓝宝石 `#A8B8F0` 只允许作极少量选中点缀（本图里只有“前缀共享”的缓存块）。
- 板子上**不写字**；名称是平放的 HTML 标签，贴着各板最右侧顶点，随相机移动。
- 不编造数据；“3 次读写合并为 1 次”之类只是示意，页面上要标“示意图”。
- 减少动效（`prefers-reduced-motion`）下停在静态最终态，无循环。
- 无 WebGL2 时显示一句提示（保留文字内容，不要空白）。
- 六种语言的标签：标签文字走现有 `data-ui` 机制，不要写死中文。
- 不要 git commit / push；改依赖要先报告。

## 场景（右侧三条标题切换，文案取自 `assets/site-data.js` 的 `engine`）

1. **沿用生态，减少适配**：顶层三条光线；中层左 18 个小块（vLLM 多模块）+ 右 1 个整块（C++ 融合）；底层 12×5 计算单元，稀疏点亮。
2. **容纳更长的上下文，处理更多并发**：顶层三路请求流动；中层 KV 缓存方块，三档亮度表示三个请求，前缀共享块用蓝宝石淡色；一块 SSD 薄板从底部抽出；底层点亮约三分之一。
3. **从推理需求出发，设计整机**：顶层 8 条扫描层；中层三个算子滑拢成一个融合块；底层大面积点亮并缓慢脉动。

切换时板间距、内容出现、SSD 出入都要有过渡（settle 缓动，错开约 70ms）。

## 质感要求（用户明确提出）

- 真玻璃：折射、厚度、**磨砂雾感**（亮处向外晕一圈淡雾，不是清玻璃），圆角板、圆弧倒角、倒角边缘光、缓慢流动的反光。
- 里面的小块必须**嵌在玻璃内部**，被磨砂层盖住，不能看起来浮在表面；小块带小圆角，不要尖角。
- 整体不要过亮：银白元素用亮度层级，磨砂雾压住高光。
- 极致化（用户全部要，不计性能）：屏幕空间辉光（bloom，克制）、板子下方的地面反射、景深（远处板略虚）、板自身的工艺细节（缺口、刻线、微小凹槽、边缘斜切）。
- 鼠标移动时相机轻微环绕、高光跟随；静止时板子极轻浮动、高光缓慢漂移。

## 技术方案

- three.js 用**固定版本**，自托管在 `website/assets/vendor/`，生产里不走外部 CDN。选型建议：`MeshPhysicalMaterial`（transmission、thickness、roughness、ior、clearcoat、attenuation）、`RoundedBoxGeometry`、`RoomEnvironment` 或自建 PMREM 环境、`EffectComposer` + `UnrealBloomPass` + `BokehPass`/DOF。注意 three 的 transmission 只折射不透明物体、且不折射别的透射物体，所以多层玻璃叠放要自己处理（可参考参考版：逐层绘制，抓取已绘内容再折射）。
- 站点没有构建步骤。如需把 three 与插件打成单个文件，可一次性用 esbuild 打包并提交产物，不把构建引入部署；如何取舍先问用户。
- 部署在 Cloudflare 免费版：静态文件免费不限量，单文件需小于 25 MiB，不要引入 Worker 请求（`_routes.json` 只放行 `/visitor-language.js`）。
- 离屏时暂停渲染（IntersectionObserver），DPR 上限 2，窗口缩放重建。

## 验证（交付前必须做，并把截图给用户）

在真实 GPU 浏览器里渲染（不要用软件 GL 的无头模式），三个场景分别截 1440 宽、768 宽、390 宽；检查：控制台无报错或警告；帧时间；鼠标移动与场景切换；减少动效；无 WebGL2 的提示；标签不遮挡、不溢出；手机无横向滚动。跑不了的要说明，没验证的不要写成已验证。
